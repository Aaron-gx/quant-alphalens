# AI 架构 + Harness 能否支撑"较高准确率"——实证诊断

> 2026-09-23 · 基于源码逐文件复核 + `data/jijin.db` 全表盘点
> 结论先行：**harness 撑得住运行，准确率撑不住；问题不在 harness，而在引擎层。**

---

## 一、分层结论

| 问题 | 结论 | 依据 |
|---|---|---|
| 能否支撑系统运行？ | **能** | 三层引擎 + 对账闭环 + 交易员 harness + API/调度/回放全部跑通，工程完成度高 |
| 能否保证较高准确率？ | **当前不能** | 真实对账 0/2 命中；校准 34 次全部未生效；量化样本外增量恰好 +0.0pp |

关键区分：**架构保证的是"可归因、可检验、可纠错"，不是"准确"。**
本项目 harness 的诚实度反而是全项目最强的资产——它自己把问题暴露了出来。

## 二、决定性实证数据

全部来自 `data/jijin.db`，无一项为推测。

| 指标 | 实测值 | 含义 |

## 三、三个结构性瓶颈（根因，按影响排序）

### 1. 量化引擎在跑纯 numpy 线性模型 ← 最直接的原因

- `requirements.txt` 中 `lightgbm` / `scikit-learn` 被**注释掉**，标注 `# enable at P4`。
- `core/predict/quant.py::_backend()` 三级降级 → 落到 `SoftmaxRegression`（线性）。
- 代码里已写好的 36 特征 LGBM 配置（`n_estimators=200, num_leaves=31`）**从未被激活**。
- 线性模型在日频三分类上学不到非线性 → **这就是"命中率 = 基准命中率"的根因**。

### 2. `flat_threshold_pct = 1.0` 让任务退化为"多数类猜谜"

- 600 条样本里 flat 占 45%（272/600），多数类基准命中率天然就是 56.7%。
- 模型只要"多猜 flat"就能拿到体面分数 → **最危险的"准确率幻觉"**。
- 56.7% 看起来能看，实际零信息量（模型 +0.0pp）。

### 3. 样本量与覆盖双重不足

- 标的池：11 条预测里 9 条是 016665，模型文件只有 5 个。
- **周期覆盖断裂**：`fuse()` 只在 `next_day` 执行；`one_week` / `one_month` / `quarter`
  **既无量化交叉验证、也无校准**（样本 0）→ UI 上 3/4 的输出是 LLM 裸主观概率。
- **校准池无标的分层**：`_bundle_path()` → `calib_{llm|quant}_{horizon}.pkl`，
  scope 只有引擎维度。5 个波动率/信噪比差异很大的标的混池训练，互相污染。

## 四、其他已确认的准确率隐患

| # | 隐患 | 位置 | 后果 |
|---|---|---|---|
| 1 | `quant_weight=0.35` 写死，未按样本外表现自适应 | `pipeline.py` | 给"零增量"模型 35% 权重 = 把 LLM 的 35% 概率稀释到噪声 |
| 2 | LLM 输出抖动大 | 016665 同日 4 次预测（id 7~10） | next_day 的 down 概率 0.38/0.42/0.30/0.42 反复横跳（temp=0.3） |
| 3 | 实盘对账仍用 `iloc[-1]` | `evaluator.py::_actual_price` | v2.1 只修了 `replay=True` 分支；补账/延迟对账会污染 CalibSample |
| 4 | 资产类型误判痕迹 | pred id=2/3 | 场外基金 016665 被标成 `stock`；`asset_type_hint` 需调用方显式传 |
| 5 | 可学误差分支从未真实触发 | 归因器 | 仅 2 条到期预测全被判 `noise`，`forecast_error` 链路只有合成测试覆盖 |

## 五、修复优先级（按 ROI 排序）

### P0 — 立即做，直接决定准确率上限

1. **装 `lightgbm`**：解除 `requirements.txt` 注释并 `pip install`。
   代码已写好，一行之差就能从"线性零增量"跃升到"能学非线性"。**最高 ROI。**
2. **`flat_threshold_pct` 从 1.0 降到 0.5**，或改造成"绝对涨跌幅回归 + 阈值分类"两段式，
   让类别分布不再被 flat 垄断，恢复任务辨识度。
3. **融合权重自适应**：改为按样本外 Brier 反推最优权重，并加门控
   —— 量化引擎无增量时权重归零，而非固定 0.35。

### P1 — 积累样本，决定长期上限

4. 扩大标的池并把每日预测批量化（LLM 池需 ≥40 条；按每日 10 标的，约 4 天可达门槛）。
5. 校准池按标的分层（或至少把标的类型/波动率作为特征引入）。
6. 补账/延迟对账一律走 `replay=True` 口径，避免 `iloc[-1]` 污染样本。

### P2 — 结构性

7. 对外只承诺 **Brier 质量 + 相对基准增量 + 置信度可靠性**，不再承诺命中率数字。
8. 补齐基线对照（随机 / 多数类 / 买入持有），否则无法判断模型是否真有信息量。
9. 把 `one_week` / `one_month` / `quarter` 也接入量化融合与校准。

## 六、架构侧应当肯定的资产

这些不是空谈，是本次诊断中确认真实存在且质量较高的部分：

- **三层评估**（单笔 / 组合 / 记忆有效性）—— 记忆有效性这层是 v1.0 完全没有的。
- **Brier + 基准命中率对照** —— 自带照妖镜。"零增量"这个问题就是它自己暴露的。
- **walk_forward 严格样本外** + 时序切分 75/25，不偷未来。
- **"打不过基准就退回 identity"** 的诚实机制 —— 不硬用坏模型。
- **归因四分类**（beta / noise / forecast_error / decision_error）—— 防 AI 自我强化错误。
- **记忆证据门**（candidate → active 需 ≥3 条独立证据，反证超 1/3 自动降级）。
- **回放的时点截断铁律** —— 宁可少给工具，也不给能偷看未来的工具。
- **熔断 / 成本上限 / 幂等保护 / 全链路留痕**。
- 设计文档自我标注 11 项未知区，并保留错误结论作为教训样本。

## 七、必须校准的预期（最重要的一条）

日频方向预测的信噪比天然极低。专业量化机构日频三分类样本外能稳定超过基准
**2~3pp 已属优秀**。"保证较高准确率（如 85%）"这个目标本身需要重新定义。

本系统应当承诺的是：

> **概率校准质量（Brier 优于基准）+ 相对基准的稳定增量 + 可信的置信度分桶**

而不是命中率数字。架构能保证"可归因、可检验、可纠错"，
但**不能创造信息量**——这一点 README 里已有所意识
（"这是系统的诚实回答：日频方向预测信噪比低"），但目标表述仍需同步收敛。

### 改造后必须记住的结论（不要再从命中率找安慰）

**本特征集在日线上没有可提取的方向 alpha。** 这不是实现缺陷，
而是实证结论：所有变体的样本外 BSS 在 h≥5 上均为负，
h=1 最好的也只有 +0.005 量级（且 μ 收缩系数 λ 收敛到 0，即模型自认无技能）。

因此内核的设计目标已从"更准"改为两条，且都已验证成立：

1. **无害**：无技能时 λ→0 退化为气候学基线（BSS≡0，不劣于"永远猜多数类"），
   融合权重被门控归零（不再拿固定 0.35 把噪声灌进 LLM 概率）。
2. **可验**：BSS、命中率增量、三种基准（多数类/随机/气候学）全部暴露；
   `engine_report()` 可直接读出"哪个周期根本没模型 / 内核是否陈旧 / 有无技能"。

要继续提升，正确方向是**换信息源**（更长历史 / 更高频 / 另类数据 / 跨标的截面），
而不是在这个模型上继续调超参。
