# 量化引擎内核 v3：从"退化三分类"到"回归 + 经验分布 + 无技能自动归零"

> 2026-09-23 · 承接 `AI架构与准确率诊断-2026-09-23.md`
> 一句话结论：**准确率没有变高，但"不可验证的假准确率"被换成了"可验证的真实能力边界"。**
> 这不是妥协——在日线特征集确实没有方向 alpha 的前提下，这是唯一诚实的"最优解"。

---

## 一、这次改了什么（7 项，逐条可验）

| # | 改动 | 改前 | 改后 | 为什么 |
|---|---|---|---|---|
| 1 | **预测目标** | 三分类（涨/平/跌） | 前向收益回归 μ → 残差分布导概率 | 平盘占 57% 时三分类必然退化成"永远猜平盘"：命中率体面、BSS≤0 |
| 2 | **概率导出分布** | 正态 CDF（σ 有参数假设） | **训练残差经验分布（ECDF）** | 日收益峰度 ~9，正态低估 P(\|r\|<1%) 约 0.14 |
| 3 | **μ 收缩 λ** | 无 | λ ∈ {0,0.1,…,1}，**1-SE 规则**取最小 | 结构性保证：λ=0 即退化为气候学基线（BSS≡0），绝不比无脑更差 |
| 4 | **样本外协议** | 普通滚动切分（**无 purge**） | **purged + embargoed** walk-forward | 标签用到 close[t+h]，不 purge 就是标签泄漏 → 样本外指标系统性偏乐观 |
| 5 | **后端** | `requirements` 里 lightgbm 被注释 → 实际跑 numpy 线性逻辑回归 | LightGBM 回归器（→sklearn GBDT→numpy 岭回归三级降级） | 线性模型学不到非线性；且**装了也要修 Windows DLL 崩溃**（见第四节） |
| 6 | **融合权重** | 固定 0.35 | 按样本外 BSS 自适应 + **技能门控**（BSS≤0 → 权重 0） | 给零信息量模型固定 35% = 把 LLM 概率稀释成噪声 |
| 7 | **缓存失效判定** | 特征集 + 阈值 + 后端等级 | 追加 **`kernel` 版本标记** | 换内核而特征名恰好不变时，"跑的还是旧内核"从 UI 上完全看不出 |

配套修复（本次一并落地，否则上述改动在实盘跑不出效果）：

- **`kline_count` 400 → 700**：400 根时 h=1 只剩约 85 条样本外样本、h=60 只剩约 25 条。
- **`jobs/scheduler.py` / `POST /model/train` 的 `count=250` 改为读配置**：
  250 根 → 有效样本 189 < 门槛 258 → **一条样本外样本都产不出来**。
  表现为"量化照常出概率、`has_skill` 恒 false、融合权重恒 0"，
  而日志与接口全部返回 ok=true——**这是最危险的一类静默失效**。
- **`/model/train` 支持基金/指数标的**：原实现只取股票 K 线，基金根本重训不了。
- **对账取价改为逐 horizon 按到期日取价**（`core/verify/evaluator.py::_price_for`）：
  旧实盘口径给同一标的四个周期共用"评估时刻最新价"，只要评估日 ≠ 到期日
  （停机补账 / 手动触发 / 周末顺延），next_day 的"实际涨跌"就变成季度涨幅，
  并被写进 CalibSample 直接教坏校准层。

## 二、离线性证据：消融对照（`scripts/quant_bench.py`）

协议：10 标的 × 1200 根日线，purged + embargoed walk-forward，3 个周期。

### 2.1 分布假设是**主导因素**，不是模型选择

同一批标的、同一个岭回归，**只换概率导出方式**：

| 概率导出 | 命中率（中位） | BSS（中位） |
|---|---|---|
| 正态 CDF | 0.2340 | **−0.7928** |
| 经验分布 ECDF | 0.4615 | **−0.1555** |
| **差** | **+0.2275** | **+0.6373** |

原因由 `scripts/diag_kurtosis.py` 定位：日收益**尖峰厚尾**，过量峰度中位数 **9.18**；
真实 P(|r|<1%) = **0.5711**，正态只给 **0.4309** → 系统性低估平盘质量 +0.1402，
把"平盘"永远压在 argmax 之外。**所以正态不是"近似"，是错的。**

### 2.2 没有哪个方案有真正的方向 alpha

| 变体 | h=1 BSS | h=5 BSS | h=20 BSS |
|---|---|---|---|
| A_legacy（旧生产实现，三分类逻辑回归） | +0.0075 | −0.0232 | −0.0832 |
| B_clf_lgbm（LightGBM 分类器） | −0.1555 | — | — |
| G_logit_new（新特征 + 逻辑回归） | +0.0096 | −0.0283 | −0.1524 |
| **D_reg_emp / F_ridge_emp + λ（本次采用）** | **≈ +0.003** | **−0.0072** | **−0.1357** |

判读：
- 三分类在 h=1 微正、h≥5 转负 —— **微正来自 λ 不存在时的过拟合噪声，不是信息**。
- LightGBM 分类器全面为负 —— 更强模型在无信号数据上只是更快地记住噪声。
- 采用方案的 h=1 优势极小、h=20 仍为负 —— **如实说明：本特征集在日线上无方向 alpha。**

### 2.3 λ 的 1-SE 规则：把"过拟合验证集"这一步堵死

验证切片只有几十条样本，Brier 上 1% 的"优势"完全在噪声内。
直接取 argmin 等于让 λ 去拟合验证集噪声——**实测把 h=20 的 BSS 从 ~0 推到 −0.13**。
改用 1-SE 规则（在与最优值相差 <1 个标准误的候选里取**最小** λ）后，
h=1 的 λ 回落到 0.00、BSS 回到 +0.0047 附近。

## 三、生产验收：`scripts/verify_quant_v3.py`（2 标的 × 4 周期）

| 项目 | 结果 |
|---|---|
| 后端 | `lgbm`（**确认真的在跑 LightGBM，不是 numpy 兜底**） |
| 内核标记 | `reg_emp_lam_v3` 已写入 pkl，旧内核模型自动判为待重训 |
| 样本外样本 | 四周期全部产出（h=1 约 485 条 / h=60 约 365 条），**此前 h≠next_day 为 0** |
| 概率自洽 | 四周期概率和 = 1、非退化（max < 0.999） |
| λ | 多数周期 λ = 0.0 —— **模型自己承认择时无技能** |

| 自学习池 | quant 引擎样本 600 条（`source=walk_forward`），此前仅 2 条 eval 样本 |

生产 BSS（中位）：next_day −0.019 / one_week −0.035 / one_month −0.133 / quarter −0.024。
**与离线基准同量级 —— 说明基准结论可迁移，没有"基准跑新内核、生产跑旧内核"。**

## 四、踩过的坑（否则下一个接手的人会重踩）

### 1. Windows 上 LightGBM 必须先 `import sklearn`

`lib_lightgbm.dll` 的原生运行时依赖（OpenMP/BLAS）需先由 sklearn 的依赖链加载；
否则 DLL 内惰性函数指针为 NULL，任何 `fit` 调用都抛
`OSError: access violation reading 0x0`。

| 前置导入 | 结果（各 3 次） |
|---|---|
| 什么都不导 | FAIL / FAIL / FAIL |
| `import sklearn` | OK / OK / OK |
| `import lightgbm.sklearn` | FAIL（**不能替代**） |

已固化在 `core/predict/quant.py::_ensure_lgbm()`；
对照实验脚本：`scripts/probe_lgb_sklearn.py`。

### 2. 绝不要在 Windows 上 `pip install --force-reinstall` 含 numpy 的包

它会先卸载 numpy、再在安装 scipy 时因 WinError 5 失败 → **venv 直接废掉**。
修复方式是 `pip install "numpy>=1.26,<3.0" scipy` 把 numpy 装回来。

### 3. 内核版本标记不是"锦上添花"

换内核但特征名/阈值/后端都没变时，三道缓存检查全部放行旧模型——
继续跑旧内核而 UI 上毫无异常。`KERNEL_TAG` 是唯一能挡住这种情况的闸门。

## 五、必须说清的边界（不要美化）

1. **准确率没有提高。** 本特征集在日线上没有可提取的方向 alpha，
   所有诚实的样本外指标都指向这一点。
2. **本内核的价值是"无技能时无害 + 有技能时可验"**：
   - 无害：λ→0 退化为气候学（BSS≡0，不劣于无脑），融合权重被门控归零（不稀释 LLM）；
   - 可验：BSS / 命中率增量 / 基准对照全部暴露在 `engine_report()` 与模型状态里。
3. **"日线 + 28 个技术指标"这条路基本走到头了。** 想拿真增量需要换信息源
   （更长历史 / 更高频 / 另类数据 / 跨标的截面），而不是继续调这个模型的超参。
4. **上游预期要同步收敛**：对外承诺"概率校准质量 + 相对基准增量 + 置信度可靠性"，
   **不承诺命中率数字**（详见诊断文档第七节）。
